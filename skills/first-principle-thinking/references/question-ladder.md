# The question ladder

Climb it for every convention and habit, and for data with thin evidence. Stop at the rung that settles the assumption, and record which rung that was.

## Rung 1: Why?

Ask "why is it done this way?" and then ask why of the answer. Usually three to five times. Stop when the answer is one of:

- a person ("the first PM set it up like this"),
- a tool ("it is the template's default"),
- an accident of history ("it made sense when the reports were printed"),
- a real constraint (go to rung 2 and check it).

If the chain ends at a person, tool or accident, the assumption is a candidate for release.

## Rung 2: What is actually true?

Split the assumption into the part that is true and the part that is packaging. Example: "every slide needs a title" splits into "the audience needs to know what this moment is about" (true, perception) and "that must be a line of text at the top" (packaging, template).

- The true part becomes a constraint (step 5).
- The packaging is released.

## Rung 3: What would have to be true?

Ask what the world would need to look like for this assumption to be the right call here. Then check whether the world looks like that.

- If yes, the assumption is grounded. Re-tag it data (with the source) or physics.
- If no, release it, and write one line naming what it was protecting, so nothing important is lost when it goes (bullets protect "the audience can read it later without the speaker"; if that need is real, it becomes its own constraint).

## Recording

For each assumption write: `#n, tag, rung reached, grounded or released, one line`.

## Hypothesis form (used in step 7)

`If [change], then [observable result], measured by [metric or observation]. Cheapest test: [test]. Cost: [time or money]. Kill if: [result that proves it wrong].`

A test is cheap when it can run today with what is at hand: a quick mock, five people, an existing log, one generation run. Order tests by cost, cheapest first, and run the first before building anything.
